# sharecli v0.8.0

Release cut for the Q3–Q8 tray-dashboard wave plus the T-70 Sparkle delta-update
scaffolding. This tag exercises the full T-70 release pipeline end-to-end.

## Headline changes

- **Tray dashboard overhaul (Q3–Q8).** Resource meters, channel picker,
  composite health pill, thermal popover stats, menubar title, keyboard
  landmarks, and a unified `Sources/ShareCLITray/ChannelPicker.swift` are
  all live in `ShareCLITray.app`. Branches: `feat/q-dash-2-polish-and-overview`,
  `feat/ac-007-56-tray-gate-host-watch-ui`, `feat/ac-007-57-tray-thermal-visual`,
  `feat/ac-007-58-swift-health-thermal`, `feat/ac-007-59-popover-stats-thermal`,
  `feat/ac-007-62-swift-menubar-title`, `feat/dashboard-keyboard-landmarks`.
- **Sparkle auto-update (Q6 + t-69 + wire-sparkle-channels).** Channel-aware
  Sparkle feed resolution is in place. The dashboard toolbar now wires the
  channel picker into `SPUUpdaterDelegate.feedURLString(for:)`; the per-channel
  appcast files produced by `scripts/build-appcast.sh` are installed into
  `ShareCLITray.app/Contents/Resources/` by `scripts/install-tray-macos.sh`.
  Branches: `feat/t-69-sparkle-channels`, `feat/wire-sparkle-channels-toolbar`.
- **Composite health metric (WBS T-95).** `wire-pill-shared-health` merges
  per-process resource samples into a single composite health signal
  consumed by the dashboard pill, the menubar title, and the CLI
  `sharecli-fleet health` report. Branch: `feat/wbs-T95-composite-metrics`.
- **`proc --sort cpu/age/name` (proc-sort-limit).** `--sort` now accepts
  `cpu`, `age`, and `name` keys; help text in `src/commands/proc.rs` is
  updated to reflect the new keys. Branch: `feat/proc-sort-limit`.
- **12 new FUSE tests (q-fuse-test-depth).** Negative dentry cache,
  next-mount smoke, agent parity (fuse-cow-agent-parity), and
  Feb-recovery coverage. Branch: `feat/q-fuse-test-depth`.
- **5 Dependabot CVEs closed.** Transitively pulled bump of `playwright`
  to 1.61.1 and substrate update; tracked under
  `chore/bump-playwright-1.61.1`, `chore/bump-substrate-57ba6be`, and the
  `fix/dependabot-triage-20251007*` series.

## Release pipeline

- `scripts/build-appcast.sh` produces per-channel
  `dist/appcast/appcast-{stable,beta,alpha}.xml` feeds (signed via
  Sparkle's `generate_appcast` when the toolchain is available, otherwise a
  documented `UNSIGNED_FALLBACK_REQUIRES_GENERATE_APPCAST` placeholder).
- `scripts/install-tray-macos.sh` invokes the appcast builder with
  `--install` and copies the generated feeds into
  `ShareCLITray.app/Contents/Resources/`.
- The appcast XML schema follows `docs/appcast-template.xml`:
  `<enclosure>` carries `url`, `length`, `sparkle:version`,
  `sparkle:shortVersionString`, and `sparkle:edSignature`;
  `<sparkle:channel>` tags the feed for the right audience; binary deltas
  live in a `<sparkle:deltas>` block when a prior archive is present.

## Out of scope (deferred)

- v0.8.0 is an **appcast-pipeline** release, not a source release. The
  `sharecli-ipc` / `sharecli-ffi` artifacts and the signed
  `ShareCLITray-0.8.0.zip` are produced by CI
  (`.github/workflows/release.yml` + the new `appcast.yml`) from the tag
  push and are not part of this local tag exercise.
- The `VERSION` file on `main` (and in this worktree) currently reads
  `0.1.0`; the CI release workflow is the source of truth for the
  `CFBundleShortVersionString` baked into the eventual `.app`. Operators
  cutting a *production* v0.8.0 should bump `VERSION` to `0.8.0` in the
  same PR that promotes this tag, then re-run `build-appcast.sh` so the
  feed's `sparkle:shortVersionString` matches the bundle.
